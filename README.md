# CarePass — 가족 금융 대리권 지갑

2026 AI Blockchain Challenge in Daegu **대상** 수상작
(주최 iM뱅크 · 대구디지털혁신진흥원, 본선 2026-10-22) · 팀 연다(Open)

계좌를 통째로 넘기는 위임이 아니라, AI가 감시하는 업무별·한도별 금융 대리권을 블록체인으로 증명하는 지갑입니다.
고령자·장애인처럼 금융 대리 관리가 필요한 시민과 그 가족을 위한 서비스이고, 별도 앱이 아니라 iM뱅크 앱의 한 기능으로 통합되는 형태를 전제로 디자인했습니다. iM뱅크 홈에서 CarePass로 진입합니다.

## 무엇을 푸는가

고령의 부모를 대신해 가족이 금융을 처리하는 일은 이미 일상이지만, 현실의 방법은 통장과 비밀번호를 넘기는 것입니다. 한번 넘기면 범위도 한도도 없고, 나중에 분쟁이 생겨도 누가 무엇을 승인했는지 남지 않습니다. 성년후견은 절차가 무겁고 되돌리기 어렵습니다.

CarePass는 그 사이를 메웁니다. 병원비·공과금처럼 목적을 나눠 한도만큼 권한을 주고, 요청이 들어오면 AI가 평소 패턴과 대조해 판정하고, 승인·거부 이력을 해시로 체인에 남깁니다. 권한은 언제든 회수할 수 있고, 결제처가 실재하는 요양기관인지와 청구서가 진짜 그 기관이 발행한 것인지를 함께 검증합니다.

등장인물은 셋입니다. 어머니(위임자)가 권한을 주고, 딸(대리인)이 결제를 요청하고, 아들(공동보호자)은 결제 권한 없이 평소와 다른 건만 통지받아 이의제기합니다.

## 둘러보는 순서

처음 열었다면 데모 모드 하단의 시나리오 버튼을 이 순서로 눌러 보는 것이 가장 빠릅니다.

1. `위임장 직접 서명` 은 건별 승인을 대신하는 설정 시점의 일회성 동의입니다. 서명과 위임장 해시가 체인에 올라갑니다.
2. `정상 병원비 8만원` 다음에 `이상 120만원 병원비` 를 누르면 같은 경로에서 판정이 어떻게 갈리는지 보입니다.
3. `청구서 QR · 사칭 검증` 은 이름만 베낀 청구서가 전자서명 불일치로 보류되는 지점입니다.
4. `한도 아래로 쪼개기(구조화)` 는 한 건씩 보면 평소 금액대라 z-score로는 잡히지 않는 공격입니다.
5. `은닉 SOS 시연` 에서 승인 PIN에 `1122` 를 넣으면 겉으론 정상 승인되지만 실제로는 비공개 통보가 갑니다.

오른쪽 인스펙터의 `AI 판단`·`기관 인증`·`블록체인 원장` 탭을 함께 보면 각 판정의 근거를 확인할 수 있습니다. `직접 조작(수동)` 에서 금액을 입력하면 판정이 실시간으로 바뀝니다.

## 사용자 화면과 인스펙터를 나눈 이유

고령자와 가족이 보는 화면에는 쉬운 말만 노출합니다. 실시간 판정은 `안전 / 주의 / 확인 필요` 세 가지로만 표시하고 z-score나 μ·σ 같은 기술 지표는 숨깁니다. 그 판단 근거인 규칙 엔진과 z-score 계산 과정은 인스펙터에서만 볼 수 있습니다. 인스펙터는 동작을 보여주기 위한 계층이고 실제 앱에는 없습니다.

## 어떻게 막는가

### 판정 엔진

한도·보호선 같은 규칙과 가구별 z-score에 더해, 한도 바로 아래 반복 결제를 잡는 구조화 탐지와 청구서-결제 매칭(기관·발행일·중복·금액)을 함께 씁니다. 금액만 보는 축 하나로는 사칭이나 청구서 조작을 원리상 잡을 수 없기 때문입니다.

판정 결과는 보류와 보호자 알림으로 나뉩니다. 전부 보류시키면 평상시 마찰이 커지므로, 확실한 건만 막고 애매한 건은 막지 않되 보호자에게 즉시 알리고 이의제기 창구를 엽니다.

### 공공데이터 결제처 확인

건강보험심사평가원 「전국 병의원 및 약국 현황」 2026.6. 기준에서 대구광역시 소재 병원·의원·치과·한의원·약국 5,607곳을 추출해(보건소·보건지소·보건진료소 제외) `data/daegu-medical.json` 으로 가공했습니다. 페이지에 내장해 오프라인에서도 동작하고, 가공 과정은 `python data/tools/build_daegu_medical.py` 로 재현할 수 있습니다. ([보건의료빅데이터개방시스템](https://opendata.hira.or.kr/op/opc/selectOpenData.do?sno=11925), 공공누리 제1유형)

대리인이 병원비 결제처를 검색하면 등록 여부와 종별, 위치를 보여주고, 목록에 없는 곳이면 금액과 무관하게 임시 보류합니다.

등록 시점 조회는 일회성 관문이라 그 뒤 폐업한 기관은 영영 확인되지 않습니다. 그래서 서버가 하루 한 번 스스로 심평원을 재조회해 기관 마스터를 갱신합니다(Vercel Cron). 기관 단위로 보관하므로 호출량이 가구 수가 아니라 기관 수에 비례하고, 앱은 갱신된 결과를 외부 호출 없이 읽습니다. 폐업이 확인돼도 목록에서 지우지 않고 비활성으로 남기며, 실재 확인이 90일을 넘긴 신뢰는 자동으로 면제가 풀려 일반 기관으로 강등됩니다. 조회 결과에 없는 기관은 `조회 안 됨` 으로만 표시합니다. 조회 실패와 폐업을 구분할 수 없으므로 폐업으로 단정하지 않습니다.

### 의료기관 인증과 청구서 전자서명

이름 대조만으로는 부족합니다. 사기범이 결제처 이름을 `대구의료원` 이라고 적는 것만으로 통과하기 때문에, 이름 위에 전자서명을 얹었습니다.

1. 최초 등록 단계에서 병원이 가입할 때 기관명을 요양기관 목록과 대조하고, 확인되면 기관 서명키(ECDSA P-256)를 만들어 공개키를 온체인 인증 목록에 등록합니다 (`certifyInstitution`).
2. 병원 단말이 발행하는 청구서(QR)에 기관 서명키로 전자서명합니다.
3. 앱이 청구서를 스캔하면 공개 노드에서 `institutionKey(instId)` 로 공개키를 읽어 WebCrypto ECDSA P-256으로 서명을 검증합니다.
4. 폐업·자격정지·서명키 유출 시 `revokeInstitution` 으로 인증을 취소하고 그 이력도 체인에 남깁니다.

| 청구서 | 판정 |
|---|---|
| 인증 기관이 서명한 진짜 청구서 | 서명 검증 통과, 기존 한도·이상탐지 규칙만 적용 |
| 기관명만 베끼고 다른 키로 서명한 사칭 청구서 | 서명 불일치로 임시 보류 (금액이 작아도 보류) |
| 청구서 금액과 요청 금액이 다른 경우 | 임시 보류 (대리인의 금액 부풀리기 차단) |
| 인증이 취소된 기관의 청구서 | 임시 보류 |
| 아직 인증받지 않은 기관 | 서명 검증 불가, 기존과 같이 보호자 확인 후 결제 |

시연에 쓰는 기관명은 맥락에 따라 다르게 정했습니다. 인증·신뢰·과거 이력에는 심평원 공개 데이터에 있는 실존 기관명(대구의료원·경북대학교병원 등)을 쓰고, 인증 취소 이력은 상호에 불리한 사실이므로 가상의 `○○재활요양병원(시연용)`, 사기 주체로 등장하는 미등록 결제처도 가상의 `○○메디컬센터` 를 씁니다. 사칭 시연에 대구의료원 이름이 나오는 것은 그 기관이 사칭당하는 쪽이기 때문이고, 전자서명으로 가짜를 걸러 실제 기관을 보호하는 과정을 보여줍니다.

사칭을 실제로 막는 것은 전자서명이고, 블록체인의 역할은 여러 은행·결제대행사·지자체가 함께 조회하는 인증 기관 목록과 취소 이력의 공개 장부로 한정됩니다.

`contracts/institutions.json` 의 서명키는 브라우저에서 병원 단말이 서명하는 과정을 재현하려고 넣은 데모 키이며 보호하는 자산이 없습니다. 실서비스에서는 기관 단말의 보안영역(HSM/Secure Enclave)에 두고 앱으로 내려보내지 않습니다.

페이지를 열면 공개 노드에서 `getHistory()` 를 읽어, 원문(`contracts/demo-events.json`)으로 다시 계산한 해시와 대조한 뒤 인스펙터 `블록체인 원장` 탭에 검증 결과를 표시합니다. 노드에 연결하지 못하면 로컬 기록으로 자동 전환합니다.

시연 도중 새로 생기는 결제·승인 이벤트는 브라우저 로컬 원장에만 기록합니다. 실서비스라면 은행 기록 서버가 전송할 부분인데, 비밀키를 웹페이지에 넣지 않으려고 이렇게 나눴습니다. 해시는 Web Crypto SHA-256으로 계산하고, 비보안 컨텍스트(file://)에서는 순수 JS SHA-256으로 폴백합니다.

## 이상탐지 자체 성능평가

이상탐지를 넣었다고 말하는 것과 그게 얼마나 잡는지 보이는 것은 다릅니다. 그래서 라벨이 붙은 합성 평가셋(120가구 × 180일, 채점 대상 1,985건, 이상 162건)으로 다섯 안을 같은 데이터에 돌려 비교했습니다. 평가셋 생성기는 탐지 규칙을 일절 참조하지 않고 사기범의 목표와 행동만 모델링하므로 미탐이 실제로 발생합니다. 전체 수치와 한계는 [`eval/REPORT.md`](eval/REPORT.md) 에 있고, `eval/` 에서 `python gen_dataset.py && python evaluate.py` 로 재현됩니다.

| 안 | 정탐율 | 한도 아래 분할 | 미등록·사칭 기관 | 청구서 조작 |
|---|---:|---:|---:|---:|
| z-score만 (z≥3) | 22.2% | 10% | 5% | 24% |
| 규칙 + z | 87.0% | 71% | 100% | 100% |
| 규칙 + z + 구조화 + 매칭 (현재) | **91.4%** | 81% | 100% | 100% |

현재 안의 오탐은 바로 앞 안과 같았습니다(253건). 마찰 증가 없이 얻은 개선입니다. 차단 시점도 분할 공격 3.3번째에서 2.0번째로 앞당겨져 빠져나간 금액이 29% 줄었고, 보류와 보호자 알림을 나누면 평상시 보류율이 9.8%에서 0.8%로 떨어지면서 포착율 91.4%는 유지됩니다.

합성 데이터 기준의 자체 평가이며 실거래 성능이 아닙니다. Isolation Forest를 더한 안(정탐율 93.8%)은 오프라인 평가 전용이고 앱에 탑재하지 않았습니다.

### 확장 기능

고령자 접근성으로 인앱 큰 글씨 모드와 화면별 음성 안내를 넣었습니다. 은닉형 SOS는 강압 상황에서 은닉 PIN을 넣으면 겉보기엔 정상 승인되지만 지정기관에 비공개 통보가 가고 온체인에 `sosAlert` 가 남습니다. iM Zero AI 상담은 현재 위임 상태를 반영해 쉬운 말로 답하고 음성 질문과 낭독을 지원하는데, 데모는 외부 LLM을 호출하지 않는 상태 기반 답변이며 실서비스는 iM뱅크 AI 상담과 연계하는 것을 전제로 했습니다. 월간 대리결제 리포트는 카테고리 분해와 이상감지, 자연어 요약을 담아 지자체·요양기관용 감사 리포트로도 쓸 수 있습니다. 보안 센터에서는 대리인 단말 분실 시 원격 VC 폐기와 법정후견인 전환, 강화 인증을 다룹니다.

### 설계만 한 것

실제 은행 코어 API 연동, 생체인증, 다중서명은 설계 수준이며 구현하지 않았습니다.

## 로컬에서 실행

별도 빌드나 서버 없이 동작하는 단일 HTML 파일입니다. 저장소를 내려받아 `index.html` 을 열면 데모 모드가 그대로 동작합니다. 폰트만 CDN에서 불러오고, 오프라인이면 시스템 폰트로 폴백합니다.

```bash
start index.html      # Windows
open index.html       # macOS
```

파일로 열면 백엔드 관련 UI는 나타나지 않습니다. 서버가 없어도 앱은 그대로 동작합니다.

### 백엔드 (`api/`)

배포본에서는 Vercel 서버리스 함수가 함께 돕니다. 세션은 HMAC으로 서명한 HttpOnly 쿠키라 별도 저장소가 필요 없고, 서명이 한 글자라도 다르면 거부됩니다. 상태 변경은 서버에서 역할을 검사합니다. 대리인은 결제를 요청만 할 수 있고 승인할 수 없으며, 보호자는 결제 권한이 아예 없습니다.

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /api/health` | 배포 확인과 저장소 모드 보고 |
| `GET·POST·DELETE /api/session` | 로그인, 세션 조회, 로그아웃 |
| `GET·POST·DELETE /api/state` | 가구 공유 상태. 세 계정이 같은 위임 하나를 보고 `?since=rev` 로 폴링합니다 |
| `GET /api/audit` | 가구 공유 감사 로그. 수신 시각과 직전 항목 해시를 엮어 체인을 만들기 때문에 중간 한 건을 지우거나 바꾸면 뒤가 전부 어긋납니다 |
| `GET /api/hira` | 심평원 요양기관 조회 프록시. 인증키를 브라우저에 내려보내지 않기 위한 경유입니다 |
| `POST /api/registry-check` | 기관 마스터 읽기(`read`, 외부 호출 없음) 또는 즉시 갱신(`refresh`) |
| `GET /api/registry-cron` | 하루 1회 기관 마스터 자가 점검 (Vercel Cron) |

기록 저장소는 환경변수에 따라 달라집니다. `KV_REST_API_URL`·`KV_REST_API_TOKEN` 이 있으면 Vercel KV에 영구 저장하고, 없으면 인스턴스 메모리를 쓰며 그 사실을 화면에 그대로 표시합니다. `SESSION_SECRET` 은 세션 서명 키, `HIRA_SERVICE_KEY` 는 심평원 조회에 씁니다.

### 컨트랙트 (`contracts/`)

```bash
cd contracts
npm install
npm test                 # Hardhat 테스트 14건 (기록 권한·순서·위변조 탐지·기관 인증 발급/취소·서명 검증)
cp .env.example .env     # 테스트 전용 지갑 비밀키와 Etherscan 키 입력 (git 제외)
node scripts/gen-institutions.js        # (최초 1회) 시연용 기관 서명키 생성
npm run check:sepolia    # 기록 계정 잔액 확인
npm run deploy:sepolia   # 배포, 기관 인증 발급/취소, 시연 이벤트 기록
npm run verify:sepolia   # Etherscan 소스 검증
node scripts/sync-frontend.js sepolia   # index.html에 주소·tx·인증 기관 반영
```

## 기술

- 단일 HTML 파일, 바닐라 JS, 외부 프레임워크 없음 (폰트만 CDN: Pretendard · Noto Sans KR · JetBrains Mono)

- Web Speech API 음성 안내(TTS)와 음성 인식(STT)
- iM뱅크 공식 브랜드 컬러(민트 `#00c7a9`), 라이트/다크 테마 대응, 반응형
