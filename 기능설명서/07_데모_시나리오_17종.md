## 꼭 짚어야 할 세 개

### 12. 구조화 — 가장 강한 차별점

```
건당 한도 150,000 / 결제 145,000 (한도의 97%) / 최근 7일 내 4회 / 누적 580,000
→ z = 1.086  (임계 3 한참 아래)
→ 구조화 탐지가 hold
```

**"한 건씩 보면 평소 금액대이고 한도도 안 넘어 z-score로는 정상입니다.
한도 근접률과 빈도를 같이 봐야 잡힙니다."**

> ⚠ 이 금액은 바꾸면 안 됩니다. 29만원(한도 30만)으로 짜면 z=6.0이라 z-score도 같이 잡아버려
> "z로는 못 잡는 패턴"이라는 주장이 성립하지 않습니다.

### 13. 청구서-결제처 바꿔치기

대구의료원이 서명한 **진짜** 청구서인데 결제처만 다른 병원으로 바꿨습니다.
서명(1번 검사)은 통과하지만 **발행 기관 ↔ 결제처**(2번)에서 걸립니다. **z = 0.52**로
금액 축으로는 전혀 잡히지 않습니다.

### 4 → 12. "묻지 않는다"와 "그래도 잡는다"를 붙여서

**이 두 개를 연달아 보여주는 것이 이 서비스의 핵심입니다.**

| | 시나리오 4 | 시나리오 12 |
|---|---|---|
| 결제처 | 대구의료원 | **대구의료원 (같은 곳)** |
| 신뢰 기관 | ✅ | ✅ |
| 결과 | **즉시 승인. 아무것도 묻지 않음** | **보류** |
| 이유 | 평소 금액·한도 안 | 한도 아래로 쪼개는 패턴 |

*"믿는 병원은 묻지 않습니다. 그런데 믿는 병원에서도 쪼개면 잡습니다 — 저희가 면제한 것은
결제처 축 하나뿐이고, 금액·빈도·한도는 신뢰 기관에서도 그대로 돌기 때문입니다."*

4번만 보여주면 *"그럼 그 병원에서 마음대로 쓰면 되지 않나요"* 가 바로 들어옵니다.
12번만 보여주면 *"치매 환자가 매번 승인을 어떻게 하나요"* 가 들어옵니다. **둘은 한 쌍입니다.**

## 재검증 방법

시나리오를 고친 뒤에는 전수 스윕으로 회귀를 확인합니다.

1. `index.html` 사본에 하네스 스크립트를 덧붙여 `_sweep.html` 생성
   (`window.SCN` · `window.runScn` · `window.S` · `window.Chain`이 테스트용으로 열려 있습니다)
2. 로컬 HTTP 서버로 서빙 — `file://`로 열면 `/data` 공공데이터 fetch가 막혀 사칭 탐지가 달라집니다
3. 헤드리스 Chrome `--dump-dom`으로 결과 수집
4. 확인 항목: **예외 0 · JS 오류 0 · 렌더 정상 · 판정/한도/보호선이 기준값과 동일 · 구조화 z < 3**
5. `_sweep.html`과 서버는 반드시 정리

컨트랙트는 별도입니다 — `cd contracts && npx hardhat test` (14건).
