# 06. 확장 기능

## 1. 공동보호자 — 결제 권한 없는 감시자

아들 이준호(공동보호자)는 **결제 권한이 없습니다.** 평소와 다른 건만 통지받고 이의제기합니다.

| 기능 | 동작 |
|---|---|
| 보호자 알림함 | 예외 건은 배지를 울리고, 자동승인 건은 조용히 기록만 |
| **이의제기 (보류 중)** | 사유를 고르면 **해당 결제가 실제로 보류**되고 위임자 승인 화면에 배지가 뜸 |
| **이의제기 (이미 나간 건)** | **장부 롤백 + 신뢰 해제 + 온체인 증거 고정** — 아래 참조 |
| 확인(ack) | 문제없음으로 닫기 |
| 온체인 | `guardianNotified` / `guardianObjection` / `guardianAcknowledged` / `paymentDisputed` |

이의제기 사유는 셋 중에서 고릅니다 — *어머니가 요청한 적 없는 결제 / 금액이 과도함 / 병원 방문 사실이 없음*.
**기록으로 끝내지 않고 해당 건을 실제로 묶는 것**이 핵심입니다.

### 사후 되돌리기 — 이미 집행된 건

자동승인을 늘리면 "막지 못하고 알림만 가는" 건이 생깁니다. 그 대가를 받는 장치입니다.

```
집행된 건에 이의제기
  → 상태 disputed
  → 위임 풀 잔액 · 월 사용액 롤백
  → 신뢰 기관에서 해제 (그 병원은 다시 확인을 거침)
  → 대리인 의심 전환 (이후 보호자 알림 비통지)
  → paymentDisputed 온체인 기록
```

**한도 롤백이 중요한 이유**는 성능평가에서 나왔습니다. '월 한도 초과' 보류 160건 중 **120건이
사기가 한도를 먼저 소진해 뒤따르는 정상 결제가 막힌 연쇄**입니다. 사기의 2차 피해가
*"어머니가 정작 필요한 병원비를 못 쓰는 것"* 으로 나타나고, 롤백이 그 연쇄를 끊습니다.

**구조화 탐지가 봐야 할 공격 패턴 증거(`S.recent`)는 지우지 않습니다.**

⚠ **앱은 돈을 되찾지 못합니다.** 카드 거래취소·착오송금 반환은 은행 분쟁처리와 가맹점 동의
또는 법적 절차가 필요합니다. 앱은 **확산을 끊고, 장부를 정리하고, 증거를 고정하는 데까지**만 합니다.
그래서 **빨리 잡는 것**이 중요합니다 — 가맹점 정산 전이면 취소가 쉽고, 후면 어렵습니다.
성능평가의 *"차단 시점 2.4 → 2.0번째, 유출액 29% 감소"* 가 정확히 이 가치입니다.

> **블록체인을 쓰는 이유가 여기서 완성됩니다.** 그동안 온체인 기록은 "기록한다"에서 끝났습니다.
> 사후 이의제기는 그 기록이 **실제로 쓰이는 장면**입니다 — 가족 간 분쟁에서 "내가 승인했다/안 했다"가
> 다툼이 될 때, 은행 DB는 운영자가 고칠 수 있어 증거력이 약하지만 결제 시점에 체인에 박힌 해시는
> 누구도 바꿀 수 없습니다.

### FINRA 4512 식 비통지 분기

**보호자 자신이 의심 대상일 때는 통지하지 않는 경로**가 있습니다.
은닉 SOS가 발동하면 `S.suspectDelegate = true`가 되고, 이후 모든 보호자 알림은
`silent` 플래그가 붙어 **대리인에게 통지되지 않습니다.** 온체인 사유에도
`· 대리인 비통지(FINRA 4512)`가 함께 기록됩니다.

## 2. 고령자 접근성

| 기능 | 구현 |
|---|---|
| **큰 글씨 모드** | 헤더의 `가가` 버튼. 실제 iM뱅크 앱에는 없는 기능입니다 |
| **음성 안내 (TTS)** | 각 화면의 `🔊` 버튼. Web Speech API |
| 판정 음성 읽기 | 보류 사유와 반사실 설명을 쉬운 말로 읽어줌 |

화면에 뜨는 말은 `안전 / 주의 / 확인 필요` 세 가지뿐이고, z-score·μ·σ 같은 지표는 노출하지 않습니다.

## 3. 은닉형 SOS — 강압 상황 대응

강압적 위임에 정면 대응하는 기능입니다.

```
승인 화면에서 PIN 입력
   ├─ 평소 PIN  → 정상 승인
   └─ 은닉 PIN(1122) → 겉보기엔 정상 승인
                        │
                        ├─ 화면·토스트: "승인 완료" (주변에서는 구분 불가)
                        ├─ 지정기관(사회복지사·경찰)에 비공개 통보
                        ├─ 온체인 sosAlert 기록
                        └─ 이후 대리인은 착취 가담 의심 대상 → 비통지 분기 작동
```

대리인과 주변에서는 **일반 승인과 전혀 구분되지 않습니다.** 이것이 이 기능의 전부입니다.

> ⚠ 현재 `sosAlert`는 온체인에 **평문**으로 남습니다. 이벤트 종류 코드화가 다음 단계 과제입니다
> ([04. 블록체인](04_블록체인.md) 참조).

## 4. iM Zero AI 상담

현재 위임 상태를 반영해 **쉬운 말로** 답하는 챗봇입니다.

| 입력 | 글자 입력 또는 `🎤` 음성 질문 (Web Speech API 한국어 음성 인식) |
|---|---|
| 출력 | 화면 + 음성 읽기 |
| **외부 LLM** | **호출하지 않습니다.** 현재 상태 기반 규칙 답변입니다 |

### 답할 수 있는 것

| 질문 유형 | 답변 예 |
|---|---|
| 잔액·한도 | *"병원비는 한 번에 30만원까지, 이번 달 ○○원 더 낼 수 있어요"* |
| 결제가 멈춘 이유 | 직전 판정의 사유를 쉬운 말로 |
| 보호선 | *"생활비 보호선은 50만원이에요. 결제하고 나서 이보다 적게 남으면 결제가 자동으로 멈춰요"* |
| 한도 상향 | 냉각기간 설명 + 신뢰인 통지 |
| 위임 정지 | *"보안 센터에서 언제든 바로 멈출 수 있어요"* |
| 최근 내역 | 가장 최근 요청과 상태 |
| 블록체인 | *"나중에 바꾸거나 지울 수 없어서, 다툼이 생겨도 바로 확인할 수 있어요"* |
| **비밀번호·PIN** | **"누구에게도 알려주지 마세요. iM뱅크와 iM Zero는 절대 묻지 않아요"** + 고객센터 안내 |

### 음성 인식 보정

띄어쓰기가 틀려도(음성 인식이 '공과 금', '보호 선'으로 쪼개도) 키워드가 걸리도록
**공백을 제거한 형태도 함께 검사**합니다. 용어 교정표(`ZFIX`)와 후보 선택 UI도 있습니다.

모르는 질문은 추측하지 않고 **답할 수 있는 범위를 안내**한 뒤 iM뱅크 상담으로 넘깁니다.

## 6. 보안 센터 (화면 시뮬레이션)

| 기능 | 동작 |
|---|---|
| **원격 VC 폐기(revoke)** | 대리인 단말 분실 시 위임을 즉시 정지. 대리 결제가 바로 막히고 온체인에 기록 |
| 위임 복구 | 정지 해제 |
| **법정후견인 전환** | 법원의 후견 개시 심판이 확정되면 선임된 후견인에게 권한을 이전하고 위임을 종료 |
| 강화 인증 | 설계 표시 |

> **앱이 후견인을 지정하지 않습니다.** 성년후견은 가정법원 심판으로만 개시됩니다.
> 민법 제690조는 *수임인*의 후견 개시만 위임 종료 사유로 두고 있어, **위임인(부모)의 후견 개시는
> 법이 자동으로 끊어주지 않습니다.** 그 공백을 시스템으로 닫은 것이 이 기능입니다.
