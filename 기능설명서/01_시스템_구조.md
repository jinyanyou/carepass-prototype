# 01. 시스템 구조

## 1. 등장인물 셋 — 권한이 다르다

| | 이름 | 역할 | 할 수 있는 것 | **할 수 없는 것** |
|---|---|---|---|---|
| 위임자 | 이순자 (어머니) | `delegator` | 위임 설정, 위임장 서명, 결제 승인/거부, 위임 정지·복구 | — |
| 대리인 | 이지은 (딸) | `delegate` | 결제 **요청**, 한도 상향 **요청** | **승인 불가** |
| 공동보호자 | 이준호 (아들) | `guardian` | 예외 건 **알림 수신**, **이의제기**, 확인 | **결제 권한 자체가 없음** |

> **보호자에게 결제 권한을 주지 않은 것이 설계의 핵심입니다.** 주는 순간
> "판단 능력이 약해진 분에게 매번 확인을 받는다"는 의사능력 모순이 되살아납니다.
> 보호자는 결제의 당사자가 아니라 **감시자**입니다.

권한은 화면에서만 가리는 것이 아니라 **서버가 거부**합니다 (`api/state.js`의 `ALLOW` 표).
클라이언트를 고쳐도 `403`이 돌아옵니다.

## 2. 화면 구성

### 심사용 데모 (`/`)

```
┌───────────────────────┬──────────────────────────────┐
│  iM뱅크 앱 화면        │   데모 인스펙터 (심사용)       │
│  (실제 사용자가 보는 것)│   AI 판단 / 기관 인증 /       │
│                       │   블록체인 원장 / 서브계좌 /   │
│  상단: 계정 토글 3명    │   컨트랙트                   │
│  헤더: 가가(큰 글씨)   │                              │
│        🔊(음성 안내)   │   아래: 시나리오 17종 버튼     │
└───────────────────────┴──────────────────────────────┘
```

**사용자 화면과 심사 화면을 나눈 이유**: 고령자와 가족이 보는 뷰에는 **쉬운 말만** 노출합니다.
판정은 `안전 / 주의 / 확인 필요` 세 가지로만 표시하고 z-score나 μ·σ 같은 기술 지표는 숨깁니다.
그 판단 근거는 인스펙터에서만 확인할 수 있습니다.

### 실사용 모드 (`/app`)

인스펙터·시나리오 버튼·계정 토글을 전부 걷어내고 폰 화면만 전체로 띄웁니다.
**로그인 전에는 아무것도 보이지 않고**, 로그인한 사람의 역할 화면만 보입니다.

## 3. 돈이 어디에 있는가 — 목적 제한 서브계좌

```
본계좌 (어머니 명의, 1,000만원)
   └─ 위임 풀 300만원  ← 격리·불변. 본계좌는 건드리지 않는다
        ├─ 병원비   건당 30만 / 월 100만   (허용)
        ├─ 공과금   건당 20만 / 월 60만    (허용 · 자동납부)
        └─ 현금송금 ─────────────────────  (차단)
   └─ 생활비 보호선 50만원  ← 이 아래로 내려가는 결제는 자동 보류
```

**에스크로나 선불충전이 아닙니다.** 자금은 어머니 명의 계좌에 그대로 남고, 사용 목적과 한도만
제한됩니다. 새 계좌를 만드는 것이 아니라 **쓰던 iM뱅크 계좌에 위임 한도만 얹는 구조**입니다.

| 값 | 기본값 | 코드 |
|---|---|---|
| 위임 풀 | 3,000,000원 | `S.pool.cap` |
| 생활비 보호선 | 500,000원 | `S.protectionFloor` |
| 고액 추가인증 기준 | 500,000원 | `S.coSign` |
| 병원비 건당 / 월 | 300,000 / 1,000,000 | `S.alloc.hospital` |
| 공과금 건당 / 월 | 200,000 / 600,000 | `S.alloc.utility` |
| 현금 송금 | **차단** | `S.alloc.cash.allowed=false` |

## 4. 결제 한 건이 흐르는 길

```
① 대리인이 결제 요청
     ↓
② judge() 판정
     ↓
③ 자동승인 조건을 보는가?
     ├─ 신뢰 기관 + 정상 + 한도 내   → 즉시 승인. 아무것도 묻지 않음 (보호자 알림함에 기록만)
     ├─ 공과금 월 정기 + 정상        → 즉시 승인
     ├─ 처음 가는 병원 (정상이어도)   → 보호자 알림 + 위임자 확인
     ├─ 평소와 다름 (confirm)       → 보호자 알림 + 위임자 확인
     └─ 보류 (hold)                → 결제 안 됨 + 보호자 알림
     ↓
④ 보호자(아들) 이의제기 → 보류 중이면 묶고, **이미 나간 건이면 장부를 되돌림**
     ↓
⑤ 위임자(어머니) 승인 화면 → PIN 인증 → 승인/거부
     ↓
⑥ 온체인 기록 (이벤트 원문의 SHA-256 해시만)
```

**일상 결제는 건별로 묻지 않습니다.** 위임자가 치매·인지질환이면 건별 승인 자체를 수행하지 못하므로,
매번 묻는 설계는 서비스 전제와 모순입니다. 설정 시점의 위임장 서명으로 동의를 갈음하고,
**평소와 다른 건만** 알리거나 보류합니다. 다 물으면 알림 스팸이 되고, 다 자동이면 통제가 없습니다.

## 4-1. 신뢰 기관 — 무엇을 면제하고 무엇을 면제하지 않는가

"자주 가는 병원은 묻지 않는다"의 정확한 범위입니다.

| 축 | 보는 것 | 신뢰 기관이면 |
|---|---|---|
| **결제처** | 심평원 등록? 서명 유효? | **면제** — 그것이 신뢰의 의미 |
| 금액 | 평소 대비 편차 (z) | **그대로 검사** |
| 빈도·패턴 | 한도 아래로 쪼개는가 | **그대로 검사** |
| 한도 | 건당·월·생활비 보호선 | **그대로 검사** |

> **"재검토 없이"가 아니라 "확인 요청 없이"입니다.** 검사는 조용히 다 돌고, 통과하면 묻지 않습니다.
> 결제처 축까지 끄면 신뢰 기관에서 한도 아래로 쪼개는 공격이 그대로 통과해, 구조화 탐지가
> 스스로 만든 구멍으로 사라집니다. 실제로 고령자 금융착취는 가짜 병원보다
> **진짜 병원에서 과다하게 쓰는 쪽**이 흔합니다.

**신뢰 기관은 두 경로로 채워집니다.**

| 경로 | 내용 |
|---|---|
| **(c) 자동** | 위임 **전에** 위임자가 본인 명의로 결제한 이력에서 **3회 이상 방문한 곳**을 자동 등록 |
| **(a) 수동** | 위임 설정 화면 **"자주 가는 병원 · 확인 없이 결제"** 카드에서 직접 추가·해제 |

(c)가 **콜드스타트를 그대로 해결합니다.** 실서비스에서 이 데이터는 은행이 이미 보유한 카드·계좌
거래내역에서 나오므로 새로 모을 것이 없습니다. 데모는 그 상태를 더미로 재현합니다
(대구의료원 14회 · 경북대학교병원 5회).

(a)는 **공공데이터 목록에 있는 기관만** 고를 수 있습니다. 손으로 이름을 적게 하면 위임자를 설득해
가짜 병원을 신뢰 목록에 올릴 수 있습니다.

## 4-2. 사후 되돌리기 — 이미 나간 건

자동승인을 늘리면 "막지 못하고 알림만 가는" 건이 생깁니다. 그 대가를 받는 장치입니다.

| 층 | 조치 | 누가 |
|---|---|---|
| 1. 확산 차단 | 신뢰 기관 해제 · 대리인 의심 전환(이후 비통지) | **앱이 즉시** |
| 2. 장부 정리 | 위임 풀 잔액과 월 사용액 **롤백** | **앱이 즉시** |
| 3. 증거 고정 | `paymentDisputed` 온체인 기록 | **앱이 즉시** |
| 4. 실제 환수 | 카드 거래취소 · 착오송금 반환 | **앱이 못 함** — 은행 분쟁처리·가맹점 동의·법적 절차 |

2번이 중요한 이유는 성능평가에서 나왔습니다 — '월 한도 초과' 보류 160건 중 **120건이 사기가 한도를
먼저 소진해 뒤따르는 정상 결제가 막힌 연쇄**였습니다. 사기의 2차 피해가 *"어머니가 정작 필요한
병원비를 못 쓰는 것"* 으로 나타납니다. 롤백이 그 연쇄를 끊습니다.

단, 구조화 탐지가 봐야 할 **공격 패턴 증거는 지우지 않습니다.**

## 5. 위임장 직접 서명 — 건별 승인을 없애는 근거

호주 Banking Code 구조를 옮겼습니다.

| 요소 | 내용 |
|---|---|
| 위임장 본문 | 누구에게·무엇을·얼마까지·무엇이 차단인지·누가 입회하는지·위임 ID를 설정값에서 자동 생성 |
| 확인 3항목 | ① 병원비·공과금만 한도 내 위임 ② **대리권 오용 위험과 보호자 알림** 설명 들음 ③ **언제든 철회 가능 · 후견 개시 시 권한 이전** |
| 직접 서명 | 캔버스 서명 패드 (획을 state에 보관해 재렌더에도 유지) |
| 입회인 | 공동보호자 이준호(아들)가 기록되고 보호자 알림함에도 남음 |
| 온체인 | `delegationConsented` — **위임장 해시와 서명 해시만**. 서명 이미지·원문은 전송하지 않음 |
| 철회 | `delegationConsentRevoked` 기록 후 재서명 요구 |

서명하지 않으면 위임 설정 화면에 경고가 뜹니다 — *"한도만 정해두면 대리 결제가 시작되지 않습니다"*.

## 6. 온체인 / 오프체인 분리

| 온체인에 **올라가지 않음** | 온체인에 올라감 |
|---|---|
| 금액 · 결제처 · 카테고리 | 이벤트 원문(JSON)의 SHA-256 `dataHash` |
| 이름 · 계좌번호 | 위임 조회 키 `SHA-256("위임ID\|salt")` |
| 위임장 원문 · 서명 이미지 | 위임장 해시 · 서명 해시 |
| 청구서 원문 | 인증 기관의 서명 공개키 · 기관명 *(공개 정보라 의도적 공개)* |

자세한 내용은 [04. 블록체인](04_블록체인.md) 참조.

## 7. 서버가 없어도 동작한다

ZIP으로 받아 `index.html`을 파일로 열면 백엔드 관련 UI가 **아예 나타나지 않고**, 앱은 로컬 상태로
그대로 동작합니다. 공개 노드에 연결하지 못하면 온체인 검증도 로컬 기록으로 자동 전환되므로
**시연이 멈추지 않습니다.**
